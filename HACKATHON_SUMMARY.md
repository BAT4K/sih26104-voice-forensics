## 🚀 How to Start the Software

The system is split into an independent backend API and a Streamlit frontend dashboard.

**Start the Backend API (FastAPI):**
```bash
source venv/bin/activate
uvicorn server.api:app --host 0.0.0.0 --port 8000
```

**Start the Dashboard (Streamlit):**
```bash
source venv/bin/activate
export VFD_API_URL="http://localhost:8000"
streamlit run app.py
```

## 🧠 What ML Model Was Used?

We built a **multi-tiered forensic pipeline** designed specifically to survive harsh Indian telephony channels:

1. **The Backbone (Feature Extraction):** We used Facebook's **`wav2vec2-xls-r-300m`**. This is a massive Transformer model pre-trained on 128 languages, making it incredibly sensitive to Indic phonetic structures (like Hindi).
2. **Tier 1 (Spoof Detection):** A linear classification head on top of the backbone that outputs a binary spoof probability (Real vs. Fake).
3. **Tier 2 (Vocoder Attribution):** A secondary classification head that attributes fake audio to specific neural vocoder families.
4. **Tier 3 (Open-Set Novelty):** We fitted a Mahalanobis distance scorer on the embedding space. If an audio file lands completely outside the known clusters, it is flagged as an "Unknown System" (Zero-day attack).
5. **Cross-Session Speaker Verification:** We integrated `speechbrain/spkrec-ecapa-voxceleb` to extract robust x-vectors. This enforces strict mathematical consistency checks against a caller's enrolled history, instantly catching impersonators even if their fake voice is perfectly realistic.

## 📊 What We Trained On & Evaluated Against

**The Dataset (~6,280 total files):**
* **Real Audio:** Extracted from the **Google Fleurs** dataset (High-quality human read-speech in Indic languages like Hindi, Marathi, Tamil, Bengali).
* **Fake Audio (Deepfakes):** We generated synthetic speech using the absolute latest state-of-the-art models: **XTTS-v2, IndicF5, Suno Bark, and Parler-TTS**. 
* **Telephony Simulation:** During training, audio was dynamically routed through a G.711 / G.726 telephony degrader to force the model to learn compression-resistant forensic features.

**The Evaluation Strategy:**
We maintained strict machine learning hygiene. Using our `split_manifest.py` script, we extracted a strict **speaker-disjoint** evaluation set. This means the model never even saw the *speakers* in the test set during training, removing any possibility of a corpus shortcut. At the end of every epoch, it was tested against this holdout set to calculate the honest Validation Equal Error Rate (EER).

## 🧬 The 5 Types of AI Voice Clones Detected

Our Tier 2 vocoder attribution engine actively categorizes deepfakes into the following neural synthesis families:
1. **hifigan** (Used by XTTS-v2, Piper)
2. **vocos** (Used by IndicF5, F5-TTS - The most realistic threat today)
3. **encodec** (Used by Suno Bark)
4. **modern_codec / dac** (Used by Parler-TTS)
5. **legacy_ar** (Older architectures like WaveRNN)

## ⚠️ Current Limitations (Hackathon Prototype)

While the pipeline architecture is production-ready, there are constraints:
1. **Data Size:** While 6,280 files is an incredible dataset for a hackathon, commercial models train on millions of files.
2. **Read Speech vs. Conversational:** The real human audio used (Fleurs) is "read speech" (like reading an audiobook). Real fraud happens during noisy, conversational phone calls involving background noise, interruptions, and filler words.
3. **Compute Limits:** Training was performed on Kaggle (P100 GPUs) for 5-10 epochs. With enterprise A100 clusters, we could unfreeze more layers and scale batch sizes for even better performance.

---

## 🔮 Next Steps (Scaling to Production)

To take this from a hackathon winner to an enterprise-grade banking security product, we would:

1. **Scale the Dataset:** Integrate massive conversational datasets (like *Kathbath* or *ASVspoof 2021*) to teach the model how humans actually sound on chaotic phone calls.
2. **Modern Synthesis Engines:** Expand the training set to include synthetic voices generated by the absolute latest commercial engines (ElevenLabs, VALL-E, Voicebox, XTTS-v2).
3. **Cloud Compute Migration:** Move the `train.py` pipeline to Google Colab Pro (A100 GPUs) or GCP Vertex AI. This would allow us to completely unfreeze all 24 layers of the `wav2vec2` backbone and train for 50-100 epochs, unlocking the model's true accuracy.
